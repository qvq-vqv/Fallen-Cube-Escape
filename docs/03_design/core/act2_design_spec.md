# 🌿 《黎明魔方》第二幕：“数据爬藤”主题设计与可玩性审判方案 (MVP精简版 - 16关最终案)

本方案是经过主管 (Antigravity) 与写码者 (Codex) 充分讨论、消灭所有自相矛盾点后的最终 MVP 落地设计。
为了确保系统极高稳定性与代码零大重构风险，第二幕（L13 - L28，共 16 关）**仅保留青色数据藤蔓（障碍格）与阻燃格（防火墙）的拓扑组合**，禁止出现任何红藤、金藤、孢子点、净化格、电击眩晕或复杂卡牌工具。

---

## 1. 🎯 一句话核心卖点
> 第二幕将静态的魔方解谜升级为**“动态阻截与时空剪裁”**——玩家通过拧动魔方作为“空间剪刀”，切断藤蔓与母体的通路使其枯萎，为主角开辟安全通道，并在受限空间中与能穿过藤蔓的怪物进行周旋。

---

## 2. 🎨 玩家新鲜感来源

*   **视觉/主题新鲜感**：进入被霓虹病毒寄生的“幽荧生态区”（Glitch Biosphere）。每个面都有发光的红色病毒母体（Root）和沿格子爬行的青色藤蔓（Vine），配合科技感故障艺术（Glitch Art）视觉特效。
*   **玩法机制新鲜感**：藤蔓每 2 步向邻格扩散，封锁玩家道路。拧动魔方可切断藤蔓与其母体的路径连接（BFS 判定），失去连接的藤蔓会在回合结束时瞬间消失（割草爽感）。
*   **怪物交互不对称性**：**玩家不能走藤蔓格子（作为障碍物），但怪物（Chaser/Guardian）可以走藤蔓格子（无视藤蔓阻挡）**。这使得藤蔓成为对玩家单向封锁的通路，玩家必须通过旋转剪枝来为自己开路，同时避开在藤蔓中如履平地的怪物。

---

## 3. 🛡️ 防超模审判 (Playability Audit)

*   **对旧机制的影响**：不破坏任何已有逻辑。藤蔓仅作为动态的障碍物占位符（`cell.hasVine === true` 则对玩家 `isWalkableForPlayer === false`）。
*   **状态机与快照 (Undo)**：藤蔓状态（`vineCells` 集合与 `vineStepCounter`）完全并入 `createSnapshot` 与 `restoreSnapshot`，玩家悔棋（Undo）时藤蔓状态同步回滚，杜绝数据错乱。
*   **旋转映射 (Permutation)**：在每次 Twist 旋转结束后，`vineCells` 和 `vineSources` 的 cellId 列表通过旋转排列（permutation）进行重映射，确保视觉与逻辑完美同步。
*   **算法独立性**：剪枝 BFS 搜索使用独立的 `getVineNeighbors(cellId)` 纯物理邻接判定，不掺杂玩家/AI 的 walkability 属性，也不包含 bridge 传送门，彻底隔绝干扰。
*   **去 AP 减速化**：第一版不做复杂的 AP 减速（防 AP 状态机与寻路冲突），藤蔓对玩家仅作为**软阻挡（障碍物）**，怪物可以跨越。

---

## 🗺️ 4. 地图设计约束 (Design Constraints)

*   **地图尺寸**：统一为 **4x4 魔方**（提供充足的换线和蔓延空间）。
*   **每关推荐步数**：**4 ~ 10 步**（单局时间控制在 2 分钟以内）。
*   **敌人数量上限**：最多 **2 个**（Chaser 或 Guardian）。
*   **禁止出现的坏关卡形态**：
    *   *绝对禁止* 出现“藤蔓随机扩散导致关卡无解”；蔓延算法为**确定性扩散**（向所有未阻燃的物理邻格蔓延）。

## 🛠️ 6. 最终实现规范 (可交付 Codex 编码)

### 静态配置 (静态关卡定义在 `levels.js` 中)：
*   `vineSources: Coord[]` - 病毒母体根源坐标列表
*   `vineCells: Coord[]` - 初始已长草的格子坐标列表
*   `immuneToVine: Coord[]` - 阻燃格坐标列表
*   *注：坐标格式 `Coord` 统一为 `{ face: number, row: number, col: number }`，在载入关卡时转换为 cellId 进行处理。*

### 运行时状态 (保存在 `GameEngine` 实例中，杜绝污染 `currentLevel`)：
*   `this.vineSources = new Set<number>()` - 运行时母体 cellId 集合
*   `this.vineCells = new Set<number>()` - 运行时已长藤的 cellId 集合
*   `this.immuneToVineCells = new Set<number>()` - 运行时阻燃格 cellId 集合
*   `this.vineStepCounter = 0` - 运行时蔓延计步器
*   *注：以上四个运行态字段必须完全加入 `createSnapshot()` / `restoreSnapshot()` 以及在 `applyPermutation()` 中进行排列重映射。*

### 物理计算规则：
1.  **物理邻居定义**：使用 `getVineNeighbors(cellId)` 只获取 cell 的 3D 面物理邻居，不根据玩家或 AI 是否能走来过滤，且不包含 `bridge`（传送门）。
2.  **生长规则**：每 2 次有效玩家动作，从现有 `vineCells` 向相邻 `!immuneToVineCells` 且未长草的格子蔓延。
3.  **剪枝规则 (BFS)**：从所有 `vineSources` 出发进行 BFS 连通性搜索。未被搜索遍历到的 `vineCells` 在回合结束前全部清除（`vineCells.delete(id)`）。
