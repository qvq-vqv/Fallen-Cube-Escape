# 《黎明魔方》玩伴试玩反馈与迭代追踪看板 (Playtest Issue Tracker)

本文档记录了每一轮玩家/测试者试玩中暴露的问题、Bug、设计缺陷以及重构历史。

## 📈 版本 3.1 试玩反馈记录 (2026-06-28)
* **测试对象**：CEO 邀请的朋友试玩前六关。
* **主要目标**：打磨新手指引的流畅度、代入感与底层回合制逻辑判定。

### 🚨 新暴露的问题与 Bug 列表

| 问题编号 | 关卡 | 暴露的问题现象 | 根源分析 | 策划/技术设计方案 |
| :--- | :--- | :--- | :--- | :--- |
| **#01** | L01 | **缩放判定有严重 Bug**：鼠标拖拽旋转视角时，滚轮进度条也会误加，导致瞬间判定为完成缩放。并且**只能放大，不能缩小**，而玩家需要缩小来观察魔方全貌。 | 相机距离变动阈值过小，误把旋转时的距离抖动判定成了缩放；且 OrbitControls 的 `minDistance/maxDistance` 或交互步进逻辑限制了缩小的可用范围。 | 1. 锁死缩放的距离追踪，**只检测 `wheel` 滚轮和 touch pinch 双指捏合事件**。<br>2. 拓宽 OrbitControls 距离限制（放宽至 10~28），**鼓励并限制缩放教学的目标必须为“缩小”（Zoom Out）**。 |
| **#02** | L01 | **传送门/出口不显眼，且相机展示停留过短**。玩家还没注意到出口门（Portal），就急忙去手操旋转视角，导致后续不知道出口在哪，引起卡关。 | 出口 showcase 镜头静止时间不够，且没有明显的高亮标定（Beacon）或提示。玩家一旦好动开始拖动，相机便解锁，玩家错过了唯一的出口暗示。 | 1. 镜头拉到出口时，**锁死拖拽视角 1.5 秒**。<br>2. 在出口大门上增加一个**醒目的脉冲式高亮霓虹光圈/指示箭头**。<br>3. 弹窗增加明确提示，并在特写停留结束后再允许玩家手操转回来。 |
| **#03** | L02 | **信任值（Trust）概念脱节**。中文教程写“信任值”，ESC 界面里写“Trust”，没有统一术语，更没有机制解释。 | 1. 双语本地化不一致。<br>2. ESC 界面打开后，Trust 数值缺乏高亮，玩家不知道去哪看，也不明白信任度掉落到 50% 以下的严重后果。 | 1. 统一术语为 **`Trust / 信任度`**。<br>2. 在 ESC 界面中增加一个**极显眼的脉冲光圈指向该指标**。<br>3. 教程卡片文案显式补充：“⚠️如果信任值低于 50%，她有概率会恐慌，从而拒绝画线指令，并在格子上随机乱走！” |
| **#04** | L03 | **追击者平移感太重，没有回合制博弈感**。玩家吐槽怪物只是个单纯和平移的主角投影。 | 玩家移动与怪物移动在同一个 tick 内几乎瞬时发生，导致视觉上产生“同步平移”的错觉，而不是“我走一步，怪追一步”的回合制反应。 | **在玩家移动完全结束后，延迟 300ms~400ms 再触发追逐者移动**。此时怪物眼部红光一闪，然后再平滑位移，强化“回合制交替”的视觉感知。 |
| **#05** | L01-L06 | **关卡结算画面弹得太早**。主角还没走到传送门，胜利结算的 Canvas/Div 就跳出来了，非常突兀。 | 结算引擎仅判断了玩家到达门口那一帧的逻辑可达状态，没有等待主角 3D Mesh 彻底播放完行走动画并进入门内。 | 修改关卡胜利触发点：**必须等待 E-7 的移动动画完全结束，并且角色模型进入大门隐去 500ms 后**，再弹出结算面板。 |
| **#06** | L04 | **第四关卡关严重**。教程强制引导玩家旋转魔方最底层的轴（绕远路，反直觉）；旋转提示环太暗；Twist 概念没有细讲。 | 1. 指引的旋转路径非较优解，反直觉（人类本能想拧顶层 Y0 直接对齐）。<br>2. Twist 选定环的发光材质在环境光下不明显。<br>3. 没说明 Twist 除了对齐路，还会把地板上的钥匙和怪一起转走。 | 1. **修改指引**：把需要拧的轴改为顶层（Y0）。<br>2. 旋转按钮材质发光强度提升 3 倍，做高亮脉冲。<br>3. 提示卡片详细说明 Twist 机制对格子内怪物和钥匙的联动旋转效应。 |
| **#07** | L05 | **新手教学里遗留专业/开发词汇**（如 Y1轴、逆时针CCW等），人设有些出戏。 | 之前的教程卡片在设计时漏掉了一部分人设文案的过滤，残存了开发调试时的变量词汇。 | 检查 L01-L12 所有浮窗文本，彻底洗掉“CCW”、“Y1层”等冷冰冰的代码术语，改用自然语（例如“中间那一层”、“朝左转”）。 |
| **#08** | 全关卡 | **旋转（Twist）不消耗回合，导致怪物在旋转期间呆立不动**，不符合策略硬核感。 | 之前的关卡状态机为了简单，把旋转做成了无代价动作，导致玩家可以无限制地拧来拧去，怪物完全呆滞。 | **将 Twist 动作显式定义为消耗 1 回合**。玩家每旋转一次层，怪物（追击者和守卫）也会结算一次它们的行动（移动或警戒）。 |
| **#09** | L06 | **第六关教学关卡卡死 Bug**。教程强制玩家点击远处格子，但移动引擎仅允许玩家点击相邻格子移动，导致无法点击，完全卡住。 | 教程配置的 `targetCell` 是较远的目标格子，但在真实画线移动模式中，玩家由于行动力或相邻阻断无法一笔画达，画线器拦截了输入。 | **重新设计 L06 教学步骤**：将 `targetCell` 修改为主角当前位置**正下方的相邻格子**。第一步先引诱守卫挪开，然后第二步再教玩家走位绕后，实现真正的拉扯教学。 |

## 🛠️ 下一阶段（GPT-5.5 开发）改进要点备忘

1. `main.js`：缩放防抖判定、出口展示镜头锁、胜利延迟触发、Twist 回合数绑定。
2. `levels.js`：L04 旋转顶轴指引更新、L06 移动目标单步更新、L01-L12 浮窗去词汇化、L02 ESC 高亮位置描述、Trust/信任度中文对齐。
3. `style.css`：Esc 面板 Trust 指标的高亮增强、旋转环闪烁强化。
4. `game.js`：Twist 触发 AI 行动决策机制（在 `rotateLayer` 中添加 AI 行动时钟触发）。
