# 🛡️ escape 项目全局开发防线与避坑铁律 (Global Fail-Safe & Anti-Regression Rules)

> **适用范围**：项目主管 (Antigravity) 与 物理写码执行者 (Codex / gpt5.5) 共享，长期有效并永久牢记。
> **创建宗旨**：记录历史开发中的血泪教训（死锁、偷工减料、过载、误触），杜绝任何逻辑回归与二次返工，节省 Token 消耗。

---

## 🚨 当前共有 5 条永久牢记铁律

### 🔴 规则 1：状态机物理隔离原则 (Inspect vs Playing Isolation)
*   **起因**：关卡加载预览（Inspect 阶段）时提前触发了 `game.initLevel`，使得 `tutorialActive` 在游戏还没开玩时就被设为 true，导致教程对话和暗色遮罩拦截了屏幕，死锁了“开始行动”按钮。
*   **铁律**：`initLevel(index, isInspect)` 必须包含 `isInspect` 门锁。当 `isInspect = true` 时，**强行锁死** `tutorialActive = false`。教程只能在玩家正式点击“开始行动”进入游玩或重置关卡时激活，绝对禁止在预览及主页阶段亮起。

### 🔴 规则 2：拖拽与点击物理隔离原则 (Drag-Click Separation)
*   **起因**：引入可自由拖拽的聊天悬浮球与工具箱球后，如果玩家在屏幕上拖动它们改变位置时，在松开鼠标时很容易意外判定为点击，从而把聊天日志或道具列表错误展开。
*   **铁律**：必须在圆球的指针松开事件中做位移偏差检测（`Math.abs(up.x - down.x) > 5` 或类似阈值）。如果位移大于阈值，判定为**拖拽行为**，仅更新球的相对位置坐标；只有在位移小于阈值时，才判定为**点击行为**，触发弹窗。

### 🔴 规则 3：操作与叙事完全解耦原则 (Operation-Dialogue Decoupling)
*   **起因**：之前的教学把具体的“点击哪里”、“点碎解工具”等繁琐物理指令全部写在对白里。这导致对话人机爹味十足，且造成不识字/快速点击的玩家在没有文字后瞬间不会玩。
*   **铁律**：对白文字**彻底降权**，只用来展现情绪、世界观氛围与性格陪伴。具体的物理操作指令（该点哪、怎么转）**100% 交给系统 UI 的硬性强约束**（唯一高亮格、指向箭头、手势动画、禁用其他交互）来独立执行。

### 🔴 规则 4：视角旋转引导真实物理检测 (Bona Fide Drag Lock)
*   **起因**：开局相机执行“镜头平滑飞越自转（Camera Flight）”时，程序直接把相机的自转角度变化误判为是“玩家手动在拖拽视角”，导致玩家还没碰屏幕，视角学习步骤就自动秒播过去了。
*   **铁律**：旋转视角差值累计，**必须且只能在 `isPointerDown === true`（玩家鼠标确实按住并拖动）且 `!cameraFlight`（相机并没有处于自动飞行中）**时才进行。

### 🔴 规则 5：方案准入与拒绝“虚空吹嘘” (Strict Code Review Protocol)
*   **起因**：之前 Codex 曾在大纲和汇报中写“已做好了手机折叠与工具栏极简收拢”，但在代码层面根本没有真正实现，只是用简单的 Notch 侧滑栏应付差事。
*   **铁律**：严禁 Codex 在沟通板或提交中虚构、夸大功能的实现状态。所有的代码修改必须以真实的物理运行和主管（Antigravity）审计结果为准。**如果 Codex (gpt5.5) 在开发中想到了更优化的替代技术方案，必须在沟通板上整理为 Notice 提交主管，由主管转交用户审批，严禁自作主张。**
